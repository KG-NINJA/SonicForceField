# Sonic ForceField

PCのスピーカーとマイクを使い、反射音のドップラー変化から**接近する動き**を捉えるローカルアプリ。Three.jsでPCの周囲のフィールドを表示します。

- 接近：赤い波がPCへ収束
- 離反：青い波が外側へ拡散
- 方向不明：黄色の波と双方向の矢印
- 静止：緑のフィールド

波・矢印は模式表示です。実際の方向角・距離・位置・人数を表しません。スコアは通常は基準スペクトルからの超過dB、遮蔽時は送信音の低下dBであり、確率ではありません。

## 起動（Windows）

Node.js 20以上、Chrome / Edge、PC付近のスピーカーとマイクが必要です。この作業フォルダーでは依存関係を導入済みです。

1. `start-sonic-forcefield.cmd` をダブルクリック。
2. **http://127.0.0.1:8765** をChrome / Edgeで開く。
3. ヘッドホンを外し、OSの既定出力をPCのスピーカーにする。入力は実際のマイクを選ぶ。ステレオミキサー／ループバック入力は使用しない。
4. 「測定を開始」を押して、このローカルページのマイク使用を許可する。
5. PCの位置を固定して待つ。通常は約8秒。会話や一時的な物音は許容し、雑音が入った区間は自動除外して延長する。受信確認と校正が終わると「動きなし」になる。
6. 画面を前面に保ち、PCへ近づく。反射音の変化が続くと「接近する動きを検知」へ切り替わり、イベントが記録される。

「停止」で発音・マイク入力を終了します。非表示、音声処理停止、音声機器の変更・切断、解析遅延でも停止します。**バックグラウンド常駐の防犯アプリではありません。**

別のPCにソースをコピーした場合のみ、先に `npm ci` を実行してください。手動起動は `npm start`。8765番が使用中なら別ポートを指定します。既存プロセスを停止したり流用したりしません。

```powershell
$env:PORT = '8766'
npm start
```

## 調整と実機確認

- 初期値は20.0 kHz、送信レベル2%、感度「超敏感・大きく反応」。数値はデジタル振幅で、実際の音圧ではありません。送信レベルはUI・音声処理の両方で上限3%に制限し、自動で増幅しません。実際の音圧や安全性を保証する値ではありません。
- 「超敏感・大きく反応」は判定閾値1 dB、継続0.15秒、相対基準下限−72 dB、側帯の絶対下限−100 dBFSです。遮蔽は2 dB低下で検知し1 dB未満で解除します。弱い変化や環境音にも反応しやすくなります。数値は実測のdBのまま、検知時の波・矢印は大きく表示します。送信レベルの上限3%は維持します。
- 「微弱・低速」は周波数分解能を細かくし、弱い側帯と低速の動きを解析します。感度を上げる代わりに0.6秒の継続を必要とします。誤検知が多い場合は「高い」「標準」へ戻して再校正してください。
- 「送信音を確認できません」：画面の「受信診断」に発音前後の差が表示されます。10 dB未満、または受信ピークが−75 dBFS未満なら開始しません。受信できない問題は感度を上げても解決しないため、出力先・消音・マイクを確認してください。診断は停止後も残りますが、前回の測定値です。
- 18/19 kHzも選択できますが、これは厳密な超音波ではなく近超音波です。聞こえる・不快な場合は停止してください。
- マイクのエコー除去・ノイズ抑制・自動ゲイン制御を無効にする要求を出します。ブラウザが有効と報告した場合は測定を開始しません。ドライバ側の補正はブラウザから確認できない場合があります。
- 校正中の短い物音・音割れは除外して自動続行します。開始時の送信音確認は発音前・発音中の中央値を使い、各段階で最大8秒まで待ちます。基準校正は最大20秒まで延長します。妨害が続いて安定区間が集まらないときだけ停止して再試行を案内します。スピーカー・PCの位置や音量を変えた後は再校正してください。
- 常に大きい音、測定周波数付近の干渉、PC周辺の連続した動きまで無条件に許容するものではありません。送信音の受信条件と、監視開始後の音割れ・マイク切断時の停止は維持します。
- Bluetooth機器や高周波をカットするスピーカー・マイクでは使えない場合があります。送信音の受信に成功しても、人物からの反射を検知できる保証はありません。
- 感度「高い」は弱い変化にも反応しますが、誤検知が増える可能性があります。

実機での受入確認：無人・静止状態で60秒、その後、接近と離反を各10回試し、距離・機器・設定・見逃し・誤検知を記録してください。これは確認手順であり、検知距離や成功率の保証値ではありません。校正時に強い一定の干渉音があると、その帯域の感度が落ちる場合があります。

人と物体の区別や静止した人の在席確認はできません。扇風機、動く物、別の高周波音などにも反応します。遅い動き・横方向の動き・小さい反射は検知できない場合があります。

## デモと検証

「デモを開始」は合成音声を実測と同じFFT・判定器へ入力します。微細な動き・接近・遮蔽・離反・混在・静止を選択できます。マイク許可も発音も不要で、常に「DEMO · 模擬信号」と表示します。**デモ成功は実機検知成功ではありません。**

```powershell
npm test
npm run lint
npm run typecheck
npm run check
npm run build
```

ビルドは `dist/` に実行用ファイルとThree.jsをコピーします。`dist/` はNode.jsがあれば `npm install` なしで起動できます。開発用のテスト・検証コマンドはソースフォルダーで実行してください。

自動テストは合成波形での方向判定、会話中の校正、一時的な物音・音割れからの回復、連続妨害のタイムアウト、校正後の遮蔽・信号喪失と復帰、許可失敗、開始キャンセル、停止・再開始、配信範囲を対象とします。実際の人物検知距離・成功率は未検証です。

## 処理と参照

発音なし約1.6秒 → 発音あり約1.8秒の差が10 dB以上かつ受信ピークが−75 dBFS以上か確認 → 約4秒の基準校正 → 検知。16384点Blackman窓FFT（48 kHz時、約2.93 Hz刻み）、実サンプルレート対応。「超敏感」「微弱・低速」は送信音の±18 Hz、それ以外は±35 Hzを除外し、±450 Hzまでの側帯を解析します。3つの隣接ビンに持続する基準超過を検知し、正側のみ優勢を接近・負側のみ優勢を離反とします。両側が判定閾値以上なら方向不明とします。接近・離反・方向不明のいずれも検知イベントに数えます。方向が切り替わっても強さが継続して基準を超えていれば検知し、動きの継続中は1回だけ記録します。

基準校正は直近最大120フレームの中央値から、pilotが4 dBを超えて変動した枠、測定側帯の3隣接ビンが8 dBを超えて増大した枠、クリップした枠を除外します。静かな方向への揺らぎや微小な数値ノイズは除外理由にしません。安定した80フレーム以上、ウィンドウ内80%以上の安定多数、最新フレームが安定していることを満たしてから、安定枠の90パーセンタイルを基準にします。短い物音で基準が持ち上がり感度が落ちることを抑えます。

「超敏感」以外では、校正後に送信音が基準から6 dB以上低下するか、受信が−75 dBFSを下回ると、同じ継続時間で「接近・遮蔽」としてイベントを記録します。受信が−75 dBFS以上かつ低下が4 dB未満になると通常のドップラー判定へ戻ります。完全に受信が途切れても遮蔽として測定を継続し、同じ遮蔽中のイベントは1回です。人・手・物体による遮蔽と、音量低下・スピーカー消音・通知されない入力不良は区別できません。遮蔽中はドップラー方向を判定せず、画面に理由を表示します。開始前・校正中の信号喪失は開始条件を満たさず、受信が12 dBを超えて増大した場合は再校正を求めます。

「微弱・低速」は相対基準の下限−65 dB、側帯の絶対下限−95 dBFS、判定閾値3 dB、継続0.6秒。「高い」「標準」「低い」は相対基準の下限−55 dB、絶対下限−85 dBFS、継続0.3秒。静止への復帰は0.65秒、イベント間隔は最低3秒です。FFT窓の時間幅もあるため、0.6秒はシステム全体の応答時間を意味しません。

音声はメモリ内で処理するだけで保存しません。履歴は現在のページ内の検知イベントのみ。外部API、CDN、録音送信は使用せず、HTTPサーバーは127.0.0.1のみにバインドします。
